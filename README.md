# Анализ продаж и качества доставки Olist в Excel

## О проекте

Проект представляет собой интерактивный аналитический отчёт в Excel для анализа коммерческих показателей и качества выполнения заказов бразильского маркетплейса Olist.

Основная задача — построить в Excel единый аналитический инструмент, который позволяет:

- отслеживать динамику продаж и заказов;
- анализировать структуру GMV по товарным категориям;
- контролировать сроки доставки;
- оценивать долю просроченных заказов;
- исследовать связь качества выполнения заказа с оценками покупателей.

Проект выполнен на связанных таблицах исходного датасета с использованием Power Query, Power Pivot, DAX и Excel Dashboard.

Текущая версия является MVP. На следующем этапе планируется добавить VBA-автоматизацию обновления и эксплуатации отчёта.

---

## Бизнес-задача

Предполагаемый пользователь отчёта — руководитель e-commerce / коммерческого или операционного направления.

Отчёт должен отвечать на четыре основных вопроса:

1. Как меняются GMV и количество заказов?
2. Какие товарные категории формируют основной GMV?
3. Как различается клиентская оценка в зависимости от результата выполнения заказа?
4. Как меняются качество доставки и оценки покупателей во времени?

## Данные

Использован открытый датасет **Brazilian E-Commerce Public Dataset by Olist**.

В аналитическую модель включены:

- `Orders` — заказы и даты выполнения;
- `Order Items` — товарные позиции и стоимость товаров;
- `Products` — товары и товарные категории;
- `Customers` — покупатели и география;
- `Reviews` — оценки покупателей;
- `Category Translation` — перевод названий товарных категорий.

В MVP не используются:

- Payments;
- Sellers;
- Geolocation.

### Аналитический период

Для анализа динамики используется период:

**январь 2017 — август 2018**

Неполные граничные периоды сохранены в исходных данных, но исключены из дашборда с помощью отдельного признака аналитического периода в календарной таблице.

## Подготовка данных

Исходные CSV-файлы загружаются и преобразуются в Power Query.

Основные этапы подготовки:

1. Проверка структуры таблиц и гранулярности данных.
2. Назначение корректных типов данных.
3. Проверка ключей, NULL и дубликатов.
4. Удаление неиспользуемых в MVP столбцов.
5. Объединение товаров со справочником перевода категорий.
6. Создание календарной таблицы.
7. Создание расчётных признаков доставки.
8. Подготовка отдельной таблицы отзывов уровня заказа.

## Особенности качества данных

### Несколько отзывов на один заказ

В исходной таблице Reviews содержится:

- 99 224 записей отзывов;
- 98 673 уникальных `order_id`.

Для части заказов присутствует несколько последовательных отзывов.

Чтобы один проблемный заказ не получал повышенный вес при расчёте средней оценки, была создана отдельная таблица `Reviews_OrderLevel`.

Для каждого заказа сохраняется последний отзыв по `review_answer_timestamp`.

После преобразования:

- 1 строка = 1 заказ;
- `order_id` уникален.

### Отсутствующие товарные категории

У 610 товаров отсутствовала исходная товарная категория.

Такие записи не удалялись. Для аналитического представления они объединены в группу **«Без категории»**.

На товары без категории приходится только **1,36% GMV**, поэтому они не оказывают существенного влияния на анализ крупнейших категорий.

### Отсутствующие даты доставки

Заказы без `order_delivered_customer_date` не классифицируются как доставленные вовремя или с опозданием.

Они исключаются из расчёта доли просроченных доставок.

Также обнаружено небольшое количество записей со статусом `delivered`, но без фактической даты доставки. Исходные значения не восстанавливались искусственно.
